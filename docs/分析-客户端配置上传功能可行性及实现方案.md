# 分析：客户端配置上传功能可行性及实现方案

> 状态：待用户批准后实施
> 目标版本：WLServerTest（main 分支，V6.5.1 之后）
> 关联需求：
> 1. 模拟终端上线时上传客户端配置（所有配置）
> 2. 配置上传以勾选框为开关
> 3. 配置解耦：工具所在固定目录存储配置，所有终端上传相同的配置
> 4. 增加手动触发配置上传的按钮
> 5. 失败重传：参照真实终端，网络恢复高并发场景下失败项需自动重传
> 6. 完成统计：全部上传完成后统计总耗时并显示在界面，同时显示成功与失败数量
> 总结语义：勾选框勾选 → 离线后上线自动触发配置上传；按钮 → 额外手动测试配置上传；失败自动重传 → 模拟真实终端在网络恢复高峰期的补报；完成后显示耗时与成功/失败数。

---

## 1. 结论摘要

**可行性：高，完全走既有协议与现成代码路径。**

- 协议存在且明确：接口设计说明书 3.4 节「客户端上报最新配置」= `CMDTYPE 200 / CMDID 201`，URL 为 `/USM/clientRefresh.do`，`commurl.h` 中 `URL_UPDATESTATUS` 已定义，WLServerTest 工程已包含该头文件，无需新增协议依赖。
- 老 IEG 客户端有完整参照实现：`CWLJsonParse::Fush_GetJson()` 构造全量配置 JSON，`Flush_SendClientStatusToServer` 负责 POST；其触发时机（首次心跳成功、离线→上线）与需求语义完全一致。
- 配置全集有权威定义：`CLIENT_STATUS_STRUCT`（约 100 个配置字段）覆盖接口说明书 3.4 全部字段，可供配置文件模板与 JSON 构造对齐。
- WLServerTest 现有 UI 已有同构范式（“程序白名单上传设置”的「注册后自动上传」勾选框 + 「上传白名单」按钮），新增功能照此模式扩展即可，侵入小。
- 失败重传与完成统计均为增量逻辑：老 IEG 客户端本身不做失败重传（失败仅记日志返回 FALSE），本工具按真实终端行为自建重试队列即可；统计展示可沿用现有成功/失败计数与静态文本刷新范式（如 `m_lMsgLogSuccessCount`/`m_lUploadState_SuccessCount` + `InterlockedIncrement64` + `Format("%lld")` 显示），无需新增第三方组件。

**预期改动落点**：`SendInfoToServer`（新增 201 上报函数）+ `WLServerTestDlg`（勾选框/按钮/心跳状态跟踪/统计展示）+ `ProfileConfig`（开关与重试参数持久化）+ 新增固定在 exe 目录的配置文件（如 `clientConfig.json`）+ `WLServerTest.rc`/`resource.h`（新增控件）。

**新增两点（性能压测视角）**：
1. **失败重传** —— 本工具定位是模拟大量真实终端测试平台性能：网络中断后恢复时会出现终端集中上线的高并发上报（同步还有心跳线程“离线→上线”边沿触发）；真实终端具备失败重传能力，本工具同样需要：对上报失败（网络错误/服务器回包 FAIL）的终端维护重试队列，按退避策略自动补报直至成功或达上限，从而真实还原平台在接收高峰与补报叠加时的承载表现。
2. **完成统计** —— 每一轮上传批次结束后，在界面显示该批次总耗时、成功数、失败数（并保留本次压测会话的累计值），用于量化评估平台处理能力与重传补报效果。

### 2.3 老 IEG 客户端参照实现

**JSON 构造**：`CWLJsonParse::Fush_GetJson(ComputerID, cmdType=200, CMDID=201, pClientStatusStuct, vec_DiskInfo, bIEG, stcLogServer)`（WLUtilities/WLJsonParse.cpp:3629）输出与说明书 3.4 对齐且字段更全的 JSON，覆盖 `CLIENT_STATUS_STRUCT` 全部字段：机器信息（ComputerName/IP/MAC/WindowsVersion/szCurVersion/srsVersion/WindowsX64）、自保护/实时报警/固化状态、进程保护/控制模式、U 盘/外设控制模式（CDROM/WLAN/USB 网卡/蓝牙/串口/并口/软盘/手机平板/USB 接口/WiFi 白名单）、完整性/注册表/文件/数据保护、密码策略（复杂度/长度/历史/期限/锁定阈值/Guest）、审计策略 9 项、安全选项（清虚存/隐名枚举/自动播放/共享/SYN/防火墙）、系统日志开关与周期、进程审计、上传速度/扫描速度/漏洞防护/安全检测周期/非法外联/运维 UKey 等，最后附 `hardDiskInfo` 磁盘数组与 `LogServerIP/LogServerPort`。

**发送**：`WLCConfig/WLDealMsg.cpp` 的 `Flush_SendClientStatusToServer` 组装 `Fush_GetJson` 结果后 `CWLNetCommApi::instance()->pdoPost(URL_UPDATESTATUS, sJson, &pResult)`。

**触发时机（WLMainControl/WLServerCommunicateThread.cpp，DealHeartBack 心跳回包处理）**：
- 首次心跳成功（`m_bFirst`）→ 立即上报 201；
- **离线→在线**（`!m_bOnline` → `m_bOnline = TRUE`）→ 上报 201；
- 在线→离线 → 上报 201（报告离线状态）；
- 心跳返回未注册（`HEARTBEAT_RET_NOREGISTER`）→ 上报 201。

其中“离线→上线上报 201”正是需求「勾选框勾选后，离线后上线触发配置上传」的历史原型，可直接对应移植。

**失败处理（本次新增逻辑的参照差异）**：老 IEG 客户端对 `pdoPost` 失败仅 `WriteError` 记录日志并返回 FALSE（WLDealMsg.cpp:1411-1415），**自身不做失败重传**；真实终端在实际网络中会依赖上层机制周期性补报。本工具需自建重试队列模拟真实终端的补报行为（见 5.5）。

## 4. 功能设计总览

新增右侧面板「客户端配置上传」分组，包含：
1. **勾选框**（开关）：`IDC_CHECK_AUTO_UPLOAD_CFG`「离线后上线自动上传配置」；勾选并持久化到 INI，心跳循环检测到“离线→上线”边沿时自动上报 201（仅触发一次）。
2. **按钮**：`IDC_BUTTON_UPLOAD_CFG`「上传配置」；点击后对全部已注册终端立即各上报一次 201（用于手动验证）。
3. **配置来源**：固定在 `WLServerTest.exe` 所在目录的配置文件（建议 `clientConfig.json`），所有终端共用同一份配置内容；文件中字段对齐接口说明书 3.4 / `CLIENT_STATUS_STRUCT` 全集；未找到文件时使用内置默认 JSON 并给出提示。
4. **上报通道**：每个终端组装 `[{"ComputerID","CMDTYPE":200,"CMDID":201,"CMDContent":{...}}]`，POST 到 `URL_UPDATESTATUS`（`https://{IP}:{Port}/USM/clientRefresh.do`）。
5. **失败重传**：上报失败（网络错误/服务器回包 FAIL/超时）的终端进入重试队列；重试线程按退避策略（如 1s→2s→4s→8s）自动补报，成功或达上限后移除并计入最终统计；队列上限、重试次数可通过 INI 配置。
6. **完成统计**：把“一次手动点击”或“一波自动触发”视为一个批次，记录批次开始/结束时间计算出总耗时，实时统计成功数与失败数，批次完成后把「耗时 + 成功 + 失败」显示到界面控件（同时保留会话累计值）。

## 5. 详细实现方案

### 5.1 配置解耦：固定目录配置文件

- **路径**：`GetModuleFileName(NULL)` 取 exe 路径 → 取目录 → `exe目录\clientConfig.json`。
- **格式**：JSON（与上报 JSON 字段一一对应，便于对照；免引第三方库，工程已有 jsoncpp/Json::Value 可解析）。
- **字段模板**：以接口说明书 3.4 的字段为必选基线，再按 `CLIENT_STATUS_STRUCT` 全集列出可选字段（外设控制、密码策略、审计、安全选项、上传速度、漏洞防护、安全检测、非法外联、hardDiskInfo 等）。文件内提供样例；读取时对缺失字段回退默认值（多为 0/1 开关）保证报文完整。
- **动态字段**：`ComputerIP` 用各终端注册的实际 IP（`client.GetClientIP()` / `m_ComputerID` 关联）；`ComputerID` 用各终端自身的 ComputerID；其余字段（ComputerName、ComputerMAC、WindowsVersion、各开关值）全部来自文件，保证“所有终端上传相同配置”。
- **版本字段**：文件内可选 `szCurVersion`（如 `V300R010C01B100`），缺省时用主界面“客户端版本”下拉当前值（`IDC_COMBO_CLIENT_VERSION`）。

### 5.2 上报实现（SendInfoToServer 新增函数）

新增（参考 `SendClientAdminLogToServer` 写法）：

```cpp
// SendInfoToServer.h
// HTTPS - 客户端上报最新配置（CMDTYPE=200, CMDID=201, /USM/clientRefresh.do）
BOOL SendClientConfigToServer(LPTSTR lpComputerID, LPTSTR lpComputerIP, LPTSTR lpConfigJson /*模板*/);
```

实现要点：
1. 从 `lpConfigJson`（固定模板）解析为 `Json::Value`，替换 `ComputerID`、`ComputerIP`（按终端），必要时替换 `ComputerName`/`ComputerMAC`（模板缺省时按终端值）；
2. 组装 `[{"ComputerID":...,"CMDTYPE":200,"CMDID":201,"CMDContent":{...}}]`；
3. `_snwprintf_s(url, ..., URL_UPDATESTATUS, m_strServerIP, _ttoi(m_strServerPort))`；
4. `CWLNetCommApi::instance()->pdoPost(url, (LPSTR)sJson.c_str(), &pResult)`，计数成功/失败，日志输出（`AppendLogOutput` 风格）。
5. 返回值解析：服务器回包 `CMDID=200` + `RESULT:SUC/FAIL`（可打印日志；压测场景不阻塞）。

**返回值语义（供重传判定）**：函数返回三态或通过出参返回结果：
- `OK`：pdoPost 成功且回包 `RESULT=SUC` → 计入成功；
- `FAIL_REPLY`：pdoPost 成功但回包 `RESULT=FAIL` 或 JSON 解析失败 → 视为失败，进重试队列；
- `NET_ERROR`：pdoPost 返回 FALSE（网络不通/超时/HTTP 错误）→ 视为失败，进重试队列。

### 5.3 勾选框开关与“离线后上线”自动触发

**控件**：`IDC_CHECK_AUTO_UPLOAD_CFG`（BS_AUTOCHECKBOX），初始值从 INI 读（`CProfileConfig::ReadAutoUploadCfg_FromIni()`），勾选状态变化写回 INI（`WriteAutoUploadCfg_ToIni()`）。

**状态跟踪（核心改动）**：
- 在 `client` 类新增 `volatile BOOL m_bOnline;`（或 Dlg 侧维护 `<ClientID, bool>` 映射，考虑并发安全用互斥锁保护），初始化 FALSE；
- **Windows 心跳任务线程**（WLServerTestDlg.cpp 约 6864 行循环）：每轮 `RecvHeartBeatBack_TCP` 返回后，
  - `HEARTBEAT_CMD_BACK` 且原状态为离线 → 置在线，若开关勾选则对该 client 触发一次配置上报；
  - 心跳失败（含未注册重注册后再失败）→ 置离线；
- **Linux 心跳线程**（`SendLinuxHeartbeat_HTTPS` 循环，约 12700 行）：同样按返回值（HTTPS 请求成功/失败）维护状态，离线→在线时触发；
- 只允许“边沿触发一次”，避免每轮重复上报；新增全局计数器（成功/失败）接入现有统计面板或日志输出。

**与注册的关系**：注册成功本身视为“上线”（首次心跳成功前的注册即上线）。为满足“模拟终端上线时上传客户端配置”，可在注册成功回调后若开关勾选即先上报一次；心跳线程的“离线→上线”逻辑覆盖断线重连场景。两者不冲突，建议均在开关开启时生效。

### 5.4 手动触发按钮

- 按钮：`IDC_BUTTON_UPLOAD_CFG`「上传配置」；
- 处理函数 `OnBnClickedUploadCfg()`：
  1. 校验已注册终端数（`g_vecAllClientObjects` 或全局计数，未注册先提示）；
  2. 若配置文件缺失，先提示并可用内置默认模板；
  3. 记录批次开始时间（`GetTickCount64`）；
  4. 遍历全部已注册 client（加锁 `g_csVecClients`），各自 `SendClientConfigToServer`；
  5. 等待本轮全部结果（含后续重试收敛）后，按 5.6 刷新统计（耗时 + 成功/失败数）。
- 不依赖开关状态（用户总结：“按钮是用来额外测试配置上传功能”），即手动按钮任何时候都可用。

### 5.5 失败重传机制（新增）

**设计目标**：模拟真实终端在网络中断恢复、终端集中上线时的高并发上报与补报行为——网络恢复瞬间，心跳线程会批量触发“离线→上线”上报，叠加此前失败的补报项，形成平台真实承受的压力模型。

**队列结构**（WLServerTestDlg.cpp 或独立新文件，如 `CfgUploadRetry.h/.cpp`）：

```cpp
struct CfgUploadRetryItem {
    CString     strComputerID;
    CString     strComputerIP;
    std::string strJson;        // 已替换终端字段的最终报文
    int         nRetryCount;    // 当前已重试次数
    ULONGLONG   ullNextTry;     // 下次允许重试的时间点（GetTickCount64）
};
// 全局：互斥锁 g_csCfgUploadRetry + std::vector<CfgUploadRetryItem>
// 上限：g_nCfgRetryQueueMax（默认如 10000，防长期断网堆积）
```

**入队/去重**：`SendClientConfigToServer` 返回非 OK 时，若队列中已有同一 `ComputerID` 的未决项则更新（不重复入队），否则追加；达队列上限时丢弃最早项或直接告警（建议丢弃最早项并记日志）。

**重试节奏**：独立重试线程（或复用心跳线程每轮末尾轮询）：
- 每轮扫描队列，仅处理 `ullNextTry <= GetTickCount64()` 的项；
- 重发调用 `SendClientConfigToServer`：成功 → 移除并计成功；仍失败 → `nRetryCount++`，按退避计算下次时间（建议 1s → 2s → 4s → 8s，最大重试次数 `g_nCfgUploadMaxRetry` 默认 4，均可 INI 配置）；
- 达 `g_nCfgUploadMaxRetry` 仍失败 → 移除并计失败；
- 防重试风暴：每轮最多处理 N 项（如 50），不足时 `Sleep(100)` 再扫，避免与心跳/上报请求互相挤压。

**高并发说明**：网络恢复瞬间成功率可能短期偏低，大量项进入重试队列属正常现象，正是“平台性能压测”需要的压力；重试节奏按配置控制，既还原真实终端补报，又避免本工具自造无限风暴。

### 5.6 完成统计与界面展示（新增）

**统计口径**：
- **成功**：服务器回包 `RESULT=SUC`；
- **失败**：`RESULT=FAIL` 或网络错误且重试耗尽（重试中的项不计失败，避免中间状态污染最终数字）；
- **本批次**：一次手动点击 / 一波自动触发（注册回调 + 离线→上线边沿）为一批次；批次开始 `GetTickCount64()` 记录，批次结束（该批所有终端请求完成且重试队列中本批项收敛）计算总耗时；
- **累计**：本次压测会话内配置上传成功/失败总数，供长期观察。

**数据结构**（Dlg 成员或全局，原子操作）：

```cpp
LONG64      m_lCfgUploadSuccessCount;   // InterlockedIncrement64
LONG64      m_lCfgUploadFailCount;
ULONGLONG   m_ullCfgBatchStartTick;     // 批次开始时间
volatile BOOL m_bCfgBatchRunning;       // 是否有批次在跑
```

**界面展示**：
- 在「客户端配置上传」GroupBox 内新增静态文本 `IDC_STATIC_CFG_UPLOAD_STAT`（多行/自动换行），文本格式：
  ```
  最近批次：耗时 12.3 秒，成功 150，失败 3
  累计：成功 450，失败 6
  ```
- 更新时机：手动按钮批次完成后、自动触发一波收敛后、重试队列清空或本轮不再产生新增请求时；耗时 = `(GetTickCount64() - start) / 1000.0` 秒（保留 1 位小数），若批次仍在进行中可显示“进行中”。
- **线程安全**：计数用 `InterlockedIncrement64`；从网络/重试/心跳线程更新 UI 一律 `PostMessage`/`SendMessage` 到主线程再 `SetDlgItemText`，避免直接跨线程操作控件。

## 7. 风险与注意事项

1. **并发压力**：高并发（数百/上千终端）下“离线→上线”边沿可能集中在同一时刻，瞬时产生等量 HTTPS 上报；重试机制会在此基础上叠加补报，是压测要还原的真实压力，但也可能二次冲击平台——通过 `CfgUploadMaxRetry`/重试节奏配置控制在合理范围；触发时建议按线程/小批次错峰（如每次心跳轮次内限流、或上报间隔极短的 sleep），并接入“成功/失败”统计观察。若仅作功能验证，可默认关闭重试或设小重试次数。
2. **服务器兼容性**：`clientRefresh.do` 返回 `SUC/FAIL`，压测环境需确认服务器对重复/高频配置上报的容忍度（失败重传会带来重复请求）；若服务器无该接口对应版本（V300R011C01/C11 已确认存在），需实测验证。
3. **字段口径**：模板字段名必须与协议一致（注意 `dwFilePotectStatus` 拼写、`wRestrictAnonymous` 大小写等历史命名）；用 `Json::Value` 处理时避免字符串手拼引入格式错误。
4. **配置文件缺失**：程序不应崩溃；缺省回退内置模板并提示路径，保证功能可验证。
5. **状态跟踪并发安全**：心跳任务多线程访问 `g_vecAllClientObjects`，新增在线状态读写需沿用 `g_csVecClients` 锁或使用 `Interlocked` 原子操作。
6. **与既有预留控件不冲突**：`IDC_CHECK_AUTO_WL`（注册后自动上传白名单）已存在但未实现逻辑，本次新增控件使用新 ID，不抢占预留位；后续如需实现白名单自动上传可并行。
7. **重试队列堆积/风暴**：长时间断网会导致队列堆积，需设置队列上限与最大重试次数，防止内存无界增长与恢复瞬间请求雪崩；重试中的项不计入失败数，避免统计失真。
8. **统计口径一致性**：界面必须同时标注“本批次”与“累计”口径；批次结束判定需考虑重试收敛（不能首批发送完就认为批次完成，否则失败项不会反映在最终耗时/数量里）。
