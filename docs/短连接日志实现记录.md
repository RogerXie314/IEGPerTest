## 二、数据流链路

### 2.1 前端到线程

1. 用户在日志分类面板选择外设控制/网口/UDiskPlug 复选框
2. `OnBnClickedLogAdd()` 构建 `dwTypes` 位图
3. Channel 1 (HTTPS) 中设置扩展位和子类型掩码：
   ```cpp
   if (dwTypes & 0x00008000) m_iThisTask_SelectedOperationType |= CLIENT_MSGLOG_UDISKPLUG;
   if (dwTypes & 0x00010000) m_iThisTask_SelectedOperationType |= CLIENT_MSGLOG_NETADAPTER;
   if (dwTypes & 0x03FE0000) m_iThisTask_SelectedOperationType |= CLIENT_MSGLOG_EXTDEV;
   m_dwExtDevSubTypeMask = dwTypes & 0x03FE0000;
   ```
4. `SendMessage(BM_CLICK)` 触发 `OnBnClickedButton_Lowest_AddTask()`
5. AddTask 中保留扩展位：`m_iThisTask_SelectedOperationType &= (NETADAPTER|EXTDEV|UDISKPLUG)`
6. 线程参数传递：`pHeapArgsForAllThread_MsgLog->iThisTask_SelectedLogType = m_iThisTask_SelectedOperationType;`
   `pHeapArgsForAllThread_MsgLog->dwExtDevSubTypeMask = m_dwExtDevSubTypeMask;`

### 2.2 线程发送

`ThreadFunc_MsgLogSend` 中依次检查 `CLIENT_MSGLOG_*` 位，调用对应 `SendClient*LogToServer`。

**已验证**：`[LOG-DIAG]` 日志显示 `SelectedLogType=0x00000C00`（NET+EXT），`ExtMask=0x03FE0000`（所有9种外设）。线程正确调用了发送方法。

## 三、JSON 格式演变

### 3.1 参考来源

- C# SimulatorApp `LogJsonBuilder.cs`（simulator-subprocess / simulator-inproc-dll 分支）
- IEG 源码 `WLUtilities/WLJsonParse.cpp`（ExtDevLog_GetJsonByVector、NetAdapterLog_GetJsonByVector）
- C# `CmdWords.cs`：CMDTYPE=200, CMDID(UDiskLog)=204

### 3.2 关键修正历程

| 轮次 | 发现 | 修正 |
|---|---|---|
| 1 | 初始实现 CMDTYPE=3, CMDID=203 | 改为 CMDTYPE=200, CMDID=204 |
| 2 | NetAdapter 缺少 `CMDContent:[]`/`CMDUsbContent:[]` 空数组 | 补上 |
| 3 | ExtDev 使用 `sprintf_s` + `%S` 宽字符串可能有编码问题 | 改用 `std::string` 拼接 + `CW2A(CP_UTF8)` |
| 4 | NetAdapter 有多余的 `Mac` 字段（IEG源码中无） | 移除 |
| 5 | ExtDev 参考 IEG 源码设 CMDVER=2 | 后又去掉（C# 用标准 Envelope 无 CMDVER） |

### 3.3 当前 JSON 格式

**网口 (NetAdapter)：**
```json
[{"ComputerID":"xxx","CMDTYPE":200,"CMDID":204,"CMDVER":4,
  "CMDContent":[],"CMDUsbContent":[],
  "CMDContentOtherDev":[{"Time":"2026-05-13 12:00:00","Name":"Ethernet",
    "IP":"x.x.x.x","PlugEvent":2,"OtherDevType":7}]}]
```

**外设控制 (ExtDev) — 无 CMDVER：**
```json
[{"ComputerID":"xxx","CMDTYPE":200,"CMDID":204,
  "CMDContent":[{"Time":"2026-05-13 12:00:00","UsbType":4,
    "LogContent":"CDROM使用被禁止","UserName":"-","FullPath":"-"}]}]
```

外设控制 9 种子类型 UsbType 对照：
| 分类 | mask | UsbType | LogContent |
|---|---|---|---|
| USB接口 | 0x00020000 | 1 | USB接口使用被禁止 |
| 移动设备 | 0x00040000 | 2 | 移动设备使用被禁止 |
| CDROM | 0x00080000 | 4 | CDROM使用被禁止 |
| wifi | 0x00100000 | 7 | wifi使用被禁止 |
| USB网卡 | 0x00200000 | 3 | USB网卡使用被禁止 |
| 软盘 | 0x00400000 | 5 | 软盘使用被禁止 |
| 蓝牙 | 0x00800000 | 6 | 蓝牙使用被禁止 |
| 串口 | 0x01000000 | 8 | 串口使用被禁止 |
| 并口 | 0x02000000 | 9 | 并口使用被禁止 |

**U盘插拔 (UDiskPlug)：**
```json
[{"ComputerID":"xxx","CMDTYPE":200,"CMDID":204,"CMDVER":1,
  "CMDContent":[{"Time":"2026-05-13 12:00:00","UDiskType":1,
    "serialID":"SIM-001","registerStatus":0,"DiskDriverLetter":["E:\\"],"plugEvent":1}]}]
```

## 四、当前状态

### ✅ 已完成
- CMDTYPE 从 3 修正为 200（三种日志）
- CMDID 统一为 204
- JSON 字段名和结构对齐 C#/IEG 参考
- `[LOG-DIAG]` 诊断日志确认线程正确调用发送方法
- `pdoPost` 返回 TRUE（HTTP 层面成功）
- `ExtMask` 正确传递外设子类型掩码

### ❌ 未解决
- 平台看不到这三种日志的数据（OPT/NWL/THREAT 等原有类型正常）
- 无 `[NET] Send FAILED` / `[EXT] Send FAILED` 日志 → pdoPost 返回 TRUE 但平台不收

### 🔍 可能原因
1. JSON 中的字符串编码（GBK vs UTF-8）导致字段值无法解析
2. `Time` 字段使用了硬编码的 `"2026-05-13 12:00:00"` 而非动态时间
3. URL 端点需要额外鉴权或参数
4. `pdoPost` 内部可能对某些 URL 有特殊处理

### 📋 建议排查方向
- 抓包对比 OPT 日志（正常）和 ExtDev 日志（异常）的 HTTP 请求差异
- 在 `SendInfoToServer` 方法中打印 `pResult`（平台响应体）看是否有错误信息
- 确认 `URL_LOG_USB` 和 `URL_PLUG_UDISK_INFO` 是否需要额外的查询参数
